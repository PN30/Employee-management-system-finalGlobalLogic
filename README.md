# Employee Management System

A Spring Boot 3 / Java 21 REST API with a clean single-page UI for managing **employees, departments and projects**, backed by **MySQL** and versioned with **Flyway**.

## Technology stack
| Layer | Choice |
|---|---|
| Language / runtime | Java 21 |
| Framework | Spring Boot 3.3 (Web, Data JPA, Validation) |
| Database | MySQL 8 (app) · H2 in-memory (tests) |
| Migrations | Flyway (tables, view, function, stored procedures, seed data) |
| API docs | springdoc-openapi (Swagger UI) |
| Testing | JUnit 5, Mockito, AssertJ, MockMvc, JaCoCo |
| UI | Vanilla HTML/CSS/JS served from `src/main/resources/static` |

Architecture: **Controller → Service (interface + impl) → Repository**, DTO records with Bean Validation, `@RestControllerAdvice` for errors, SLF4J/Logback logging (console + `logs/ems.log`).

## Database setup (MySQL)
1. Install MySQL 8 and make sure it is running on `localhost:3306`.
2. Set credentials (defaults are `root` / `root`):
   ```bash
   export DB_USERNAME=root
   export DB_PASSWORD=your_password
   # optional: DB_HOST, DB_PORT
   ```
3. That's it – the database `employee_management_db` is created automatically (`createDatabaseIfNotExist=true`) and Flyway builds everything on first start.
   To create it manually instead: `CREATE DATABASE employee_management_db;`

**Schema** – tables `department`, `employee`, `project`, `employee_project` (join table) with primary keys, foreign keys, unique and check constraints.
**Database objects** – view `vw_employee_details`, function `fn_get_employee_full_name`, procedures `sp_get_employees_by_department` and `sp_get_active_employees`:
```sql
SELECT fn_get_employee_full_name(1);
SELECT * FROM vw_employee_details;
CALL sp_get_employees_by_department(1);
CALL sp_get_active_employees();
```

### H2 test profile
Tests use `src/test/resources/application-test.yml` (`@ActiveProfiles("test")`): H2 in-memory in MySQL mode, schema generated by Hibernate, Flyway disabled. No setup needed.

## Flyway migrations
Migrations live in `src/main/resources/db/migration` (`V1` tables, `V2` view/function/procedures, `V3` seed data). They run automatically on startup. To run them manually:
```bash
mvn flyway:info -Ddb.username=root -Ddb.password=your_password
mvn flyway:migrate -Ddb.username=root -Ddb.password=your_password
mvn flyway:validate -Ddb.username=root -Ddb.password=your_password
```

## Run the application
```bash
mvn spring-boot:run
```
| What | URL |
|---|---|
| Web UI | http://localhost:8080/ |
| Swagger UI | http://localhost:8080/swagger-ui.html |
| OpenAPI JSON | http://localhost:8080/v3/api-docs |

## Run the tests and coverage
```bash
mvn test        # unit + repository (H2) + integration tests, generates the JaCoCo report
mvn verify      # also enforces >= 90% line coverage
```
Open `target/site/jacoco/index.html` for the coverage report.

| Test type | Location |
|---|---|
| Unit (JUnit 5, Mockito, AssertJ) | `src/test/java/com/ems/service` |
| Repository (`@DataJpaTest`, H2) | `src/test/java/com/ems/repository` |
| Integration (`@SpringBootTest`, MockMvc, H2) | `src/test/java/com/ems/integration` |

## API endpoints
**Employees** – `/api/employees`
| Method | Path | Description |
|---|---|---|
| POST | `/api/employees` | Add employee (201) |
| GET | `/api/employees` | Get all |
| GET | `/api/employees/{id}` | Get by ID (404 if missing) |
| PUT | `/api/employees/{id}` | Update |
| DELETE | `/api/employees/{id}` | Delete (204) |
| GET | `/api/employees/search?name=` | Search by name |
| GET | `/api/employees/department/{departmentId}` | Filter by department |
| GET | `/api/employees/active` | Active employees |
| GET | `/api/employees/{id}/projects` | Projects of an employee |

**Departments** – `/api/departments`: `POST`, `GET`, `GET /{id}`, `PUT /{id}`, `DELETE /{id}` (409 if the department still has employees).

**Projects** – `/api/projects`
| Method | Path | Description |
|---|---|---|
| POST / GET | `/api/projects` | Add / list |
| GET / PUT / DELETE | `/api/projects/{id}` | Get / update / delete |
| POST | `/api/projects/{projectId}/employees/{employeeId}` | Assign employee |
| DELETE | `/api/projects/{projectId}/employees/{employeeId}` | Remove employee |
| GET | `/api/projects/{projectId}/employees` | Employees on a project |

**Errors** use one JSON shape: `{ timestamp, status, error, message, fieldErrors }` – `400` validation, `404` not found, `409` duplicate email/name or rule violation.
